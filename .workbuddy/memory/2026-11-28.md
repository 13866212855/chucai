# 2026-11-28

## chucai（外出事务管理系统）上传 PDF 后前端一直“识别中...”

- 项目：Next.js 15（App Router）+ sql.js，Docker 部署，容器名 `chucai`，`redeploy.bat` 构建，宿主 7860 -> 容器 3000（`start.js` 内置 TCP 桥接 7860->3000）。数据卷 `D:\docker\chucai\data`（`llm_settings.json` + sqlite）。
- 根因（已在浏览器控制台截图与 Node vm 中复现）：`lib/pdfClient.ts` 的 `loadClientPdfJs()` 在 `/pdf.min.js` 加载回调里执行 `lib.GlobalWorkerOptions = lib.GlobalWorkerOptions || {}`，而 pdfjs-dist 3.11.174 的 `GlobalWorkerOptions` 是只读 getter，严格模式下抛 `TypeError: Cannot set property GlobalWorkerOptions of #<Object> which has only a getter`，Promise 永不 settle，`await` 永久挂起。服务端 `/api/records/infer` 本身正常（直连 7~10s 返回）。
- 修复：
  - `lib/pdfClient.ts`：只改 `GlobalWorkerOptions.workerSrc`；加载器加超时/失败清理；cMap、standard_fonts 改为同源 `/pdfjs/...`（cdn.jsdelivr / cdnjs 在该网络不可达）；PDF 解析整体超时并 `loadingTask.destroy()`。
  - `components/RecordFormModal.tsx`：抽出 `prepareFileForInference()`，每个文件 `withTimeout`，失败回退“仅文件名”；fetch 加 AbortController（150s）；新增 `inferenceStage` 进度文案；`inferenceSeqRef` 防止旧请求覆盖新请求。
  - `app/api/records/infer/route.ts`：上游 fetch 加 `AbortSignal.timeout`（文本 45s / 带图 75s，带图失败后文本重试一次），`max_tokens`，新增 `[infer]` 耗时日志。
  - `start.js`：TCP 桥接两端 close/error 同步关闭对端（避免浏览器复用半死 keep-alive 连接导致请求永久 pending）。
  - `components/OriginalFileRenderItem.tsx`：复用统一加载器，去掉 CDN 回退。
  - `scripts/sync-pdfjs-assets.mjs`：postinstall/predev/prebuild 把 pdfjs-dist 的 pdf.min.js、worker、cmaps、standard_fonts 同步到 `public/`（`public/pdfjs/` 已 gitignore）。
- 验证方式：`npx tsc --noEmit`、`npm run build` 通过；用 headless Chrome + CDP 脚本（`%TEMP%\chucai_e2e\e2e.cjs`）走“快速新建外出 -> 第 3 步 -> 上传 PDF”：旧版 45s 仍“识别中”，新版约 5s 完成回填且无控制台错误。
- 注意：本地 `npm install` 约 11 分钟（网络慢），会生成 package-lock.json / tsconfig.tsbuildinfo，验证后已删除；本地无 `.git` 提交，改动留在工作区。
